# Розпізнавання зображень за неповною гістограмою

Застосунок реалізує **перший спосіб** класифікації зі статті Р. Мельника, А. Зав'ялова
«Image Retrieval by Statistical Features and Artificial Neural Networks»:

1. яркість пікселя `Y' = 0.299·R + 0.587·G + 0.114·B`;
2. гістограма яркості на 256 бінів;
3. **неповна гістограма** — кожен бін нормується до 0..15 відносно максимуму (`round(15·h/max h)`), тобто 4 біти;
4. 256 × 4 = **1024 бінарні входи** одношарової ШНМ (сигмоїда, дельта-правило), один вихідний нейрон на клас.

Стек: ASP.NET Core 10 (Minimal API + SignalR + Serilog), бібліотека `Core` (ImageSharp, TensorPrimitives), UI на React + TypeScript (Vite, Tailwind CSS, shadcn/ui, Chart.js).

## Запуск

Потрібні .NET 10 SDK і Node.js 20+.

Запуск сервера → http://localhost:5080 з кореня репозиторію:

```bash
dotnet run --project src/HistogramClassification.Api --launch-profile http
```

Збірка проєкту `Api` сама збирає UI у `src/HistogramClassification.Api/wwwroot`: `npm install` — коли змінюються `package.json` / `package-lock.json`, `npm run build` — коли змінюються вихідні файли `src/web`. Зібрати лише API без UI: `dotnet build -p:SkipWebBuild=true`.

Режим розробки UI з гарячим перезавантаженням: запустіть сервер як вище, а в іншому терміналі `cd src/web && npm run dev` → http://localhost:5173 (запити `/api` і `/hubs` проксіюються на 5080).

Тести: `dotnet test`.

## Дані

```
Assets/
  hq-4k/      ocean/ desert/ grass/ ...   ← оригінали (кладіть самі або завантажуйте через UI)
  icons-32/   ocean/ desert/ grass/ ...   ← генерується кнопкою «Згенерувати» на вкладці «Дані»
```

- Група = папка якості, клас = підпапка. Однойменні класи з кількох груп об'єднуються.
- На вкладці «Навчання» можна вибрати всю папку `Assets` або окремі групи, ліміт зображень на клас, кількість епох, швидкість навчання, частку тесту, seed.
- Шлях до `Assets`, файлу моделі й логів налаштовується в `src/HistogramClassification.Api/appsettings.json` (секція `App`) або змінними середовища `App__AssetsRoot` тощо.

## Що де показується

| Вимога | Де |
|---|---|
| Розпаралелення | Витяг ознак і генерація іконок — `Parallel.For` по зображеннях (`Core/Progress/BatchRunner.cs`), потоків = ядер CPU. Перемикач «паралельно/послідовно» в UI дозволяє порівняти час. Навчання послідовне (онлайн дельта-правило), але скалярні добутки — SIMD (`TensorPrimitives`). |
| Налаштування ML | Епохи, η, частка тесту, seed, ліміт на клас — вкладка «Навчання». |
| Прогрес | SignalR: «оброблено N з M зображень» для ознак/генерації, «епоха e з E» + прогрес всередині епохи. Скасування — кнопка «Скасувати». |
| Лог | Вкладка «Лог» (наживо) + файл `logs/app-YYYYMMDD.log`. |
| Час виконання | Живий таймер під час операції та підсумок по етапах (ознаки / навчання), також у лозі. |
| Групи за якістю | Структура `Assets/<група>/<клас>`, вибір груп при навчанні, генерація `icons-32`. |

Модель після навчання зберігається в `models/last.json` і підхоплюється при перезапуску; її можна експортувати/імпортувати на вкладці «Розпізнавання». Там само показуються виходи нейронів, гістограма і неповна гістограма зображення. Матриця ваг кожного класу (32×32, як рис. 8 статті) — на вкладці «Навчання».
